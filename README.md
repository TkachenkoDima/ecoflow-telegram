# EcoFlow → Telegram

Telegram-бот для станцій EcoFlow: у кожній групі — **один автооновлюваний «екран»** зі станцією цієї групи, пуші про заряд і світло, статистика відключень, керування станціями й автоматизації зарядки.

```
EcoFlow BOT
🔋 Маринка 89% · ⏳ 28:34 · 🕯 2 год 54 хв      ← видно навіть у списку чатів

🔋 Маринка   14:29
▰▰▰▰▰▰▰▰▰▱  89%
⏳ Залишилось  28:34
⚡ Споживання  32 Вт
🔝 Ліміт заряду  100%
🤖 Макс. вхід  500 Вт
🔻 Мін. розряд  10%

🕯 Без світла 02:54 · з 11:34
[ 📊 Усі станції ]
[ Маринка ][ Kate ][ Router ]
[ 📈 Статистика ][ ⚙️ Керування ]
```

Рядок про світло: якщо почалось сьогодні — `💡 Світло є 01:16 · з 14:47`; якщо в інший день — з датою: `💡 Світло є 3 д 2 год 15 хв` / `з 23.10, 13:38`. Тривалість від доби — у днях, годинах і хвилинах.

**Що вміє**

| | |
|---|---|
| **Екран** | одне повідомлення в групі, оновлюється щохвилини; усі кнопки міняють його ж; через 3 хв без натискань повертається до станції групи |
| **Пуші** | пороги 50 / 25 / 10 % (свої тексти, прогноз hh:mm), «🕯 Світло пішло / 💡 повернулось» (скільки було/не було, детальний підсумок за сьогодні, попереднє); зникають самі через 3 хв (нічні — о 08:03) |
| **Станція групи** | `/pin <станція>`: пуші про пороги й список у пушах про світло — лише по ній |
| **Статистика** | тиждень / місяць / календар / день: скільки разів і скільки годин без світла, найдовше, середнє, коли найчастіше вимикають |
| **Керування** | `⚙️ Керування → станція`: ліміт заряду 80/90/100 %, мін. розряд 5/10 %, вхідна потужність |
| **Автоматизації** | ступінчаста зарядка Маринки 2 кВт → 1 кВт → 500 Вт; ручне керування має пріоритет до «🤖 Авто» |
| **Тихий режим** | 00:00–08:00 без звуку, крім 10 % |

Працює як **Cloudflare Worker** (безкоштовний тариф, перевірка щохвилини), деплой — **GitHub Actions** при push у `main`. Ні сервера, ні ввімкненого комп'ютера не потрібно.

## Як це влаштовано

| Тип станції | Звідки дані |
|---|---|
| Моделі, які віддає офіційний **EcoFlow IoT Open API** (перевірено: DELTA 3 Max Plus) | REST з підписом HMAC — `via: 'rest'` |
| Моделі, на які API відповідає `1006 current device is not allowed` (перевірено: River 3 / серійники `R65…`) | MQTT застосунку EcoFlow (логін email+пароль), protobuf — `via: 'mqtt'` |

Щохвилини воркер бере список пристроїв (онлайн/офлайн), читає REST-станції, підключається до MQTT, чекає до 15 с на пакет батареї від кожної MQTT-станції, порівнює з порогами і за потреби пише в Telegram. Стан (які пороги вже сповіщені, світло) — у Cloudflare KV, запис лише при змінах.

**Кеш для кнопок.** Останні показники cron зберігає як знімок: у пам'яті воркера → у Cache API дата-центру (безкоштовно, без лімітів) → у KV раз на 10 хв (запасний варіант). Натискання кнопок малюють екран зі знімка, якщо він не старший за 3 хв, тобто миттєво й без MQTT. Наживо (3–10 с) бот читає лише тоді, коли знімка немає або він застарів; тоді на екрані спершу з'являється `⏳ Маринка` / `завантажую…` (два короткі рядки, щоб не розширювати екран). Щойно змінені кнопкою налаштування (ліміт, вхід) показуються одразу, не чекаючи наступного знімка.

> ⚠️ **Сумісність.** Перевірено тільки на DELTA 3 Max Plus (REST) і River 3 (MQTT). Інші моделі можуть мати інші назви полів у REST або інший формат protobuf — тоді заряд буде «немає даних». Для діагностики є `tools/` (див. нижче).

## Налаштування крок за кроком

### 1. Скопіюйте репозиторій

**Use this template** / **Fork** на GitHub (або створіть новий приватний репозиторій і залийте туди код), потім:

```bash
git clone git@github.com:<ви>/<repo>.git && cd <repo>
npm install
```

### 2. Ключі EcoFlow Developer

1. Зайдіть на **developer-eu.ecoflow.com** (Європа) або **developer.ecoflow.com** (US) тим самим акаунтом, що й у застосунку.
2. **Become a Developer** → дочекайтесь листа про схвалення (буває від кількох хвилин до кількох днів).
3. Розділ **Security** → створіть **Access Key** і **Secret Key**. Secret показується один раз — збережіть.

> Акаунт у регіоні US? Змініть `API` у `src/config.ts` на `https://api.ecoflow.com`.

### 3. Перевірте свої станції

```bash
ACCESS_KEY='...' SECRET_KEY='...' node tools/check-api.mjs
```

Для кожної станції скрипт виведе готовий рядок для конфігу, напр.:

```
→ Маринка: { sn: 'D3M1XXXXXXXXXXXX', via: 'rest' }
→ UPS Kate: { sn: 'R655XXXXXXXX0001', via: 'mqtt' }
```

- `code 0` → `via: 'rest'`
- `code 1006` → `via: 'mqtt'`
- `8521 signature is wrong` → переплутані або неповні ключі.

### 4. Telegram-бот і група

1. **@BotFather** → `/newbot` → ім'я → username на `bot` → отримаєте **токен**.
2. Створіть **приватну** групу, додайте туди бота (і людей, кому треба сповіщення).
3. Напишіть у групі `/start@ваш_бот`.
4. Відкрийте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` і знайдіть `"chat":{"id":-…`. Це **chat_id** (з мінусом!).

> Не робіть групу публічною: бот показує, коли у вас немає світла, а `/status` доступний кожному учаснику.

### 5. Налаштуйте `src/config.ts`

Опишіть станції — **без серійників** (вони йдуть у секрет, щоб не світитись у репо):

```ts
export const DEVICES: Device[] = [
	{ sn: '', name: 'Вітальня', via: 'rest', cmd: 'living' },
	{ sn: '', name: 'Роутер',   via: 'mqtt', cmd: 'router' },
]
export const GRID_SOURCE = 'router' // cmd станції, по якій визначати світло
```

- `cmd` — латиницею, стане командою `/router` і кнопкою; за ним же підставляється серійник.
- `via` — з виводу `check-api` (крок 3).
- `GRID_SOURCE` — найкраще станція з **постійним** навантаженням (роутер, ПК): світло визначається за її вхідною потужністю.
- `messages` — необов'язково: свій текст для порогу, напр. `messages: { 10: 'Я скоро сяду!' }`.
- Там само пороги, тихий режим і часовий пояс.

Серійники — у секрет `DEVICE_SNS` (крок 7) у вигляді JSON `{"<cmd>": "<серійник>"}`:

```json
{"living":"D3M1XXXXXXXXXXXX","router":"R655XXXXXXXX0002"}
```

### 6. Cloudflare

```bash
npx wrangler login                          # відкриє браузер → Allow
npx wrangler whoami                         # Account ID → знадобиться для секрету
npx wrangler kv namespace create POWER_KV   # виведе "id": "…"
```

У `wrangler.jsonc`:
- замініть `"name"` на своє ім'я воркера (латиниця, напр. `ecoflow-bot`);
- замініть `id` у `kv_namespaces` на той, що вивела команда.

**API-токен для GitHub:** dash.cloudflare.com → аватар → **My Profile → API Tokens → Create Token** → шаблон **Edit Cloudflare Workers** → *Account Resources*: ваш акаунт, *Zone Resources*: **All zones** → **Create Token**.

### 7. Секрети GitHub

Репозиторій → **Settings → Secrets and variables → Actions → New repository secret**:

| Secret | Значення |
|---|---|
| `CLOUDFLARE_API_TOKEN` | токен з кроку 6 |
| `CLOUDFLARE_ACCOUNT_ID` | з `npx wrangler whoami` |
| `ECOFLOW_ACCESS_KEY` | крок 2 |
| `ECOFLOW_SECRET_KEY` | крок 2 |
| `EF_EMAIL` | email від застосунку EcoFlow (потрібен для `mqtt`-станцій) |
| `EF_PASSWORD` | пароль від застосунку EcoFlow |
| `TELEGRAM_BOT_TOKEN` | крок 4 |
| `TELEGRAM_CHAT_ID` | крок 4, з мінусом; кілька груп — через кому: `-555…,-401…` |
| `TG_WEBHOOK_SECRET` | будь-який випадковий рядок: `openssl rand -hex 32` |
| `DEVICE_SNS` | серійники станцій: `{"living":"D3M1…","router":"R655…"}` (ключі — `cmd` з `config.ts`) |

Вставляйте без пробілів і переносів рядка. Всі 10 обов'язкові (`EF_*` можна заповнити будь-чим, якщо всі станції `rest`).

### 8. Деплой

```bash
git add . && git commit -m "My stations" && git push
```

**Actions → Deploy worker** має стати зеленим. Протягом 1–2 хв у групі з'явиться `📡 Моніторинг EcoFlow запущено` зі станом станцій і кнопками. Натисніть кнопку — має прийти статус.

Далі будь-яка зміна → `git push` → автодеплой.

## Якщо щось не так

Логи воркера в реальному часі:

```bash
npx wrangler tail
```

| Симптом | Причина / що робити |
|---|---|
| Actions: `Value for secret X not found` | не додано секрет `X` (перевірте, що це вкладка **Actions**, а не Codespaces/Dependabot) |
| `8521 signature is wrong` | ключі EcoFlow у секретах переплутані або з пробілами — вставте заново, Re-run |
| Повідомлень немає, кнопки не реагують | `https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo`: якщо `url` порожній — крок деплою не дійшов до webhook; якщо Actions пише «Не вдалося визначити URL воркера» — додайте **змінну** (Variables, не Secrets) `WORKER_URL` = `https://<name>.<subdomain>.workers.dev` |
| Бот замовк після зміни налаштувань групи | група стала супергрупою, змінився chat_id (`-100…`) — оновіть `TELEGRAM_CHAT_ID` |
| `MQTT … CONNACK rc=4/5`, `EcoFlow login` | неправильний `EF_EMAIL`/`EF_PASSWORD` |
| Станція «❔ немає даних» | модель шле інший формат — зніміть дамп (нижче) і адаптуйте `src/protobuf.ts` / `readRest` |

## Керування станціями

`⚙️ Керування` → вибір станції → кнопки її команд. Набір дій — `ACTIONS` у `src/index.ts`:

| Станції | Ліміт заряду | Вхідна потужність AC | Як надсилається |
|---|---|---|---|
| `via: 'rest'` (DELTA 3) | 80 / 90 / 100 % (+ мін. розряд 5 / 10 %) | 500 Вт / 1 кВт / 2 кВт | ліміт — IoT Open API (`cfgMaxChgSoc`); потужність — MQTT (поле 54 + 125=0, офіційний API її ігнорує) |
| `via: 'mqtt'` (River 3, макс. ~305 Вт) | 80 / 90 / 100 % (+ мін. розряд 5 / 10 %) | 100 / 200 / 300 Вт | MQTT, protobuf `SetCommand` (поля 33 / 54) |

Результат підтверджується відповіддю станції або новим значенням у телеметрії. Якщо за 10 с нічого — бот пише «надіслано, перевір у застосунку». Керувати може будь-який учасник групи.

Для діагностики запису — `tools/probe/set-probe.mjs <SN> <поле> <значення>`.

## Автоматизації

`src/config.ts` → `AUTOMATIONS`. Кожне правило: станція (`cmd` або `'*'` — усі), умови і що виставити (`set`).

| Правило (за замовчуванням) | Що робить |
|---|---|
| Маринка < 80% і світло є → вхід 2 кВт | швидко заряджається між відключеннями |
| Маринка 80–89% і світло є → вхід 1 кВт | м'якше на верхній ділянці |
| Маринка ≥ 90% → вхід 500 Вт | дбайливо (працює, якщо ліміт заряду > 90%) |

Умови: `socAtLeast` / `socAtMost` (заряд), `grid: 'ON'|'OFF'` (світло зараз), `gridOnForH` (світло є вже N год), `on: 'gridOn'|'gridOff'` (лише в момент події).
Команда надсилається, лише якщо поточне значення інше. Успішні дії — без повідомлень; про збій — пуш.

Іконка рядка «Макс. вхід» (на головному і в «Керування») показує, хто ним зараз керує: `🤖 Макс. вхід 500 Вт` — автоматика, `✋ Макс. вхід 2000 Вт` — ручне (у станцій без правил — звичайна 🔌).

У «⚙️ Керування → станція» під карткою видно всі її правила, а те, що діє зараз, виділено (на головному екрані їх немає):

```
🤖 Авто
0–79% → вхід 2 кВт
80–89% → вхід 1 кВт      ← жирним, якщо діє зараз
90–100% → вхід 500 Вт
```

Умова «є світло» в тексті не пишеться (без світла заряджатись нема від чого), але перевіряється.

Опис будується з `AUTOMATIONS` автоматично — змінили правила в `config.ts`, змінився й текст.
Якщо станція не підтвердила — повтор не частіше ніж раз на 30 хв.

> Ручні дії з «Керування» мають пріоритет: після них автоматизації не чіпають станцію до «🤖 Авто».

### Ручне керування важливіше за автоматизації

Дія з «⚙️ Керування», яка змінює те саме, чим керує автоматика (за замовчуванням — **макс. вхід, Вт**), вмикає для станції **ручний режим**: автоматизації її не чіпають, **доки в меню станції не натиснути «🤖 Авто»**. Ліміти заряду/розряду автоматику на паузу не ставлять. Після «🤖 Авто» чинне правило застосовується одразу (не чекаючи наступної хвилини), а на екрані коротко: `🤖 Авто режим` / `вхід 500 Вт (90–100%)`.

Якщо ліміт заряду нижчий за поріг правила (напр. 80% при правилі «90–100% → 500 Вт»), в авто-режимі під правилами з'являється підказка (у ручному її немає — правила тоді й так не працюють):

```
⚠️ Ліміт заряду 90%
вище заряд не піде,
правило 90–100% не діє
```
У ручному режимі список правил не показується — режим видно по ✋ у рядку «Макс. вхід».

## Один «екран» у групі

`/pin <станція>` — бот створює одне повідомлення-екран для цієї групи (`/unpin` — прибрати). Екран починається з картки станції (назва, заряд), тож у списку чатів видно стан, не заходячи в групу.

| Дія | Що на екрані |
|---|---|
| нічого не натискали | «жива» картка станції групи, оновлюється щохвилини |
| кнопка іншої станції або `⚙️ Керування → станція` | «жива» картка **вибраної** станції (+ її команди в меню) |
| команда з «Керування» | спершу `⏳ Маринка / вхід → 1 кВт / надсилаю…`, потім результат + картка цієї станції |
| `📊 Усі станції` | знімок на момент натискання |
| `📈 Статистика` | розділ статистики зі своїми кнопками (див. нижче) |
| `🏠 Головна` або 3 хв без натискань | знову станція групи й головні кнопки |

Результат команди — над карткою станції:

| Результат | Текст |
|---|---|
| застосовано (станція підтвердила) | `✅ Маринка` / `вхід → 1 кВт` / `застосовано` / `✋ автоматика на паузі` (останній рядок — лише якщо дія вимкнула автоматику) |
| надіслано, але станція не підтвердила | `📤 Маринка` / `вхід → 1 кВт` / `надіслано, станція` / `не підтвердила` — перевірте значення в картці або застосунку |
| помилка | `⚠️ Маринка` / `вхід → 1 кВт` / `не вдалося:` / причина |
| «🤖 Авто» | `✅ Маринка` / `🤖 авто режим увімкнено` / `вхід → 500 Вт (90–100%)` — чинне правило застосовується одразу |

- **Станція групи** (з `/pin`): пуші про пороги — лише по ній; у «Світло пішло/повернулось» — лише вона (саме світло визначається, як і раніше, по `GRID_SOURCE`). Без `/pin` група отримує все.
- **Пуші зникають самі:** вдень через `PUSH_TTL_MIN` хв (3), уночі — о 08:03. Новий пуш того ж типу одразу прибирає попередній.
- Ваші команди (`/status`, `/pin`…) бот видаляє одразу.
- `PIN_TO_TOP = true` у `config.ts` — додатково закріпити екран угорі чату.
- **Однакова ширина.** Telegram Desktop підганяє бульбашку під найдовший рядок, тому внизу екрана є невидимий рядок фіксованої ширини (`SCREEN_WIDTH` у `config.ts`, 23), а всі рядки екранів коротші за нього — бульбашка не «стрибає» між переходами. Вужче/ширше — змініть `SCREEN_WIDTH`; якщо якийсь рядок довший, на цьому екрані бульбашка знову розшириться.
- Права бота в групі: адміністратор з «Видаляти повідомлення» (і «Закріплювати повідомлення», якщо `PIN_TO_TOP`).

## Статистика відключень

Кнопка **📈 Статистика** (або `/stats`) відкриває окремий розділ зі своїми кнопками; за замовчуванням — сьогоднішній день:

| Кнопки | Що показує |
|---|---|
| `День` / `✓ Тиждень` / `Місяць` | сьогодні (таймлайн по годинах), тиждень (пн–нд) по днях або місяць по тижнях |
| `◀  19.10–25.10  ▶` | попередній / наступний період (недоступна стрілка не показується) |
| `📅 Календар` | сітка місяця; `17•` — день з відключеннями; натиснули день → подробиці |
| день | таймлайн доби по годинах, список відключень з часом, `◀ ▶` — сусідні дні |
| `⬅️ Назад` / `🏠 Головна` | крок назад (день → календар → місяць → головна) / одразу на головну |

```
📈 Тиждень · 19.10–25.10

Пн 19.10  ▰▱▱▱▱▱▱▱  3:00
Вт 20.10  ▰▱▱▱▱▱▱▱  1 · 1:50
Ср 21.10  ▱▱▱▱▱▱▱▱  ✨
Чт 22.10  ▰▰▱▱▱▱▱▱  1 · 3:14

🔢 Відключень: 2
🕯 Без світла: 8 год 4 хв
🔆 Зі світлом: 91% часу
⏱ Найдовше: 3 год 14 хв · 22.10 11:34–14:48
➗ Середнє: 2 год 32 хв
🕐 Найчастіше без світла: 09:00–12:00
```

Як рахується:
- **Кількість** — у день, коли відключення **почалось**; **години** — фактичні в межах дня/періоду (нічне 23:00–03:00 дає 1 год одному дню і 3 год наступному).
- Смужка — частка часу без світла (8 клітинок = 100%).
- «Найчастіше без світла» — 3-годинне вікно з найбільшою кількістю хвилин без світла (від 3 відключень у періоді).
- Дні до того, як бот почав вести лог, — `—` / «немає даних», а не «без відключень».
- У пушах «🕯 Світло пішло» / «💡 Світло повернулось» — скільки світло було / не було і той самий підсумок за сьогодні:

```
💡 Світло повернулось   18:05
🕯 Не було 2 год 25 хв

📈 Сьогодні
🔢 Відключень: 2
🕯 Без світла: 5 год 38 хв
🔆 Зі світлом: 69% часу
⏱ Найдовше: 3 год 13 хв
➗ Середнє: 2 год 49 хв
```
- Лог — у KV (`outlog`), запис лише при поверненні світла, зберігається ~рік (≈40 байт на подію).
- Поки відкрита статистика, екран не оновлюється щохвилини; через 3 хв без натискань повертається на головну.

## Ліміти й вартість

Усе вкладається в безкоштовні тарифи з великим запасом:

| | Безкоштовно / добу | Використовується (2 групи) |
|---|---|---|
| Cloudflare Workers, запити | 100 000 | ~1 440 (cron) + натискання |
| Cloudflare KV, читання | 100 000 | ~30 000 |
| Cloudflare KV, записи | 1 000 | ~150 (знімок раз на 10 хв) + ~2–3 на натискання + ~3 на пуш (≈250–300 натискань/добу з запасом) |
| GitHub Actions (приватний репо) | 2 000 хв/міс | ~1 хв на push |

Без прив'язаної карти списати гроші неможливо — у найгіршому разі воркер замовкне до кінця доби.

## Безпека

- Секрети й серійники станцій зберігаються лише в GitHub Secrets і Cloudflare (зашифровано), у коді їх немає.
- `EF_PASSWORD` — пароль від акаунта EcoFlow: використовуйте унікальний.
- Бот відповідає лише в групах з `TELEGRAM_CHAT_ID`; щоб ніхто не додав його до своєї групи — @BotFather → Bot Settings → Allow Groups → Turn off; webhook захищений `TG_WEBHOOK_SECRET`.
- MQTT-доступ неофіційний: EcoFlow може змінити протокол оновленням — тоді `tools/probe` допоможе розібратися.
